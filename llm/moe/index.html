MoE流程总结（Routing/DispatchCombine）
2026-09-08 00:00

_forward_allgather

本文只描述 _is_quant == False 的 BF16 AllGather → MoE → ReduceScatter 路径。

Shape 符号

符号 含义
T_local 当前 EP rank 输入的 token 数
T AllGather 后 routed experts 实际处理的 token 数，T = T_local * ep_size
H hidden_size
I moe_intermediate_size
E routed expert 总数
E_local 当前 EP rank 持有的 physical expert 数
K 每个 token 选择的 expert 数，即 top_k
M routing 展开后的总行数，M = T * K
A 当前 EP rank 的有效 expert-token assignment 数，A = sum(expert_tokens) <= M

流程图

flowchart TD
    IN["输入 hidden_states<br/>BF16 [T_local, H]<br/>Gate 可选用 FP32 副本 [T_local, H]"]
    IN --> SAVE["保留 shared_input<br/>BF16 [T_local, H]"]
    IN --> GATE["Gate<br/>[T_local, H] -> router_logits [T_local, E]"]
    GATE --> TOPK["npu_moe_gating_top_k<br/>logits [T_local, E]<br/>-> topk_weights / topk_ids [T_local, K]"]

    TOPK --> AG["EP AllGather<br/>hidden_states: [T_local, H] -> [T, H]<br/>weights / ids: [T_local, K] -> [T, K]<br/>T = T_local * ep_size"]

    AG --> INIT["npu_moe_init_routing_v2<br/>输入: hidden_states [T, H], topk_ids [T, K]<br/>输出: sorted_tokens [M, H]<br/>expanded_x_idx [M]<br/>expert_tokens [E_local]"]
    INIT --> GMM1["GroupedMatMul 1（gate/up projection）<br/>BF16 [M, H] -> BF16 [M, 2I]"]
    GMM1 --> ACT["npu_swiglu<br/>BF16 [M, 2I] -> BF16 [M, I]"]
    ACT --> GMM2["GroupedMatMul 2（down projection）<br/>BF16 [M, I] -> BF16 [M, H]"]
    GMM2 --> FINAL["npu_moe_finalize_routing<br/>输入: expert rows [M, 1, H]<br/>weights / ids [T, K], index [M]<br/>输出: moe_output [T, H]"]

    FINAL --> RS["EP ReduceScatter<br/>[T, H] -> [T / ep_size, H]<br/>= routed_output [T_local, H]"]

    SAVE -. "可在 side_stream 上并行" .-> SHARED["Shared experts<br/>[T_local, H] -> shared_output [T_local, H]"]
    RS --> ADD["逐元素相加<br/>routed_output + shared_output"]
    SHARED --> ADD
    ADD --> OUT["result [T_local, H]"]

关键点

  1. Gate 和 TopK 在 AllGather 之前执行，所以最初的 router_logits、topk_weights 和 topk_ids 第一维都是 T_local。
  2. Routed 分支先将输入和 routing 信息 AllGather 到 [T, ...]，完成专家计算后再 ReduceScatter 回 [T_local, H]。
  3. npu_moe_init_routing_v2 分配 M = T*K 行，但当前 rank 只计算前 A = sum(expert_tokens) 个有效行。expert_tokens: [E_local] 同时表示后续 GroupedMatMul 的每组行数。
  4. Shared expert 始终使用未 AllGather 的 shared_input: [T_local, H]；开启 side stream 时，它可以与 routed expert 路径重叠，汇合前通过 event 同步。

_forward_dispatch_combine（single batch）

本文只描述 _is_quant == False 且 T_local <= max_batch_size 的 BF16 single-batch 路径；当前代码中的 max_batch_size = 128，不涉及切片和 torch.cat。

Shape 符号

符号 含义
T_local 当前 EP rank 输入及最终输出的 token 数，single-batch 下 T_local <= 128
H hidden_size
I moe_intermediate_size
E routed expert 总数
E_local 当前 EP rank 持有的 physical expert 数
K 每个 token 选择的 expert 数，即 top_k
D Dispatch 在当前 rank 分配的接收缓冲区行数；torch_npu 文档将其记为 A
V 当前 rank 实际收到的有效 expert-token assignment 数，V = sum(expert_tokens) <= D

流程图

flowchart TD
    IN["输入 hidden_states<br/>BF16 [T_local, H]，T_local <= 128<br/>Gate 可选用 FP32 副本 [T_local, H]"]
    IN --> SAVE["保留 shared_input<br/>BF16 [T_local, H]"]
    IN --> GATE["Gate<br/>[T_local, H] -> router_logits [T_local, E]"]
    GATE --> TOPK["npu_moe_gating_top_k<br/>logits [T_local, E]<br/>-> topk_weights / topk_ids [T_local, K]"]
    TOPK --> MASK["获取可选 x_active_mask<br/>[T_local] 或 [T_local, K]"]

    MASK --> DISPATCH["npu_moe_distribute_dispatch_v2<br/>输入: x [T_local, H], expert_ids [T_local, K]<br/>quant_mode = 0，执行 EP 通信和 expert 排序<br/>输出: expand_x [D, H]<br/>expand_idx [D * 128]<br/>expert_token_nums [E_local]<br/>ep_recv_counts / tp_recv_counts（一维通信元数据）"]
    DISPATCH --> COUNTS["expert_token_nums 转为 INT64<br/>expert_tokens [E_local]<br/>V = sum(expert_tokens)"]
    COUNTS --> GMM1["GroupedMatMul 1（gate/up projection）<br/>BF16 [D, H] -> BF16 [D, 2I]<br/>前 V 行为有效 expert rows"]
    GMM1 --> ACT["npu_swiglu<br/>BF16 [D, 2I] -> BF16 [D, I]"]
    ACT --> GMM2["GroupedMatMul 2（down projection）<br/>BF16 [D, I] -> BF16 [D, H]"]
    GMM2 --> COMBINE["npu_moe_distribute_combine_v2<br/>输入: expert output [D, H]<br/>ids / weights [T_local, K]<br/>expand_idx [D * 128] + Dispatch 通信元数据<br/>执行反向 EP 通信、unpermute、加权求和<br/>输出: moe_output [T_local, H]"]

    SAVE -. "可在 side_stream 上并行" .-> SHARED["Shared experts<br/>[T_local, H] -> shared_output [T_local, H]"]
    COMBINE --> ADD["逐元素相加<br/>moe_output + shared_output"]
    SHARED --> ADD
    ADD --> OUT["final_output [T_local, H]"]

关键点

  1. Dispatch 前所有 tensor 都保持本地 token 维度：hidden_states: [T_local, H]，topk_weights/topk_ids: [T_local, K]。
  2. npu_moe_distribute_dispatch_v2 同时完成跨 EP 通信和按本地 expert 排序。expand_x: [D, H] 是容量为 D 的接收缓冲区，实际参与 GMM 的行数由 expert_tokens: [E_local] 给出，即 V = sum(expert_tokens)。
  3. expand_idx、ep_recv_counts 和 tp_recv_counts 是 Dispatch/Combine 配套使用的通信元数据；业务代码只负责原样传回 Combine，不依赖其具体内容。
  4. 两次 GroupedMatMul 和 SwiGLU 都保持 Dispatch 缓冲区的第一维 D；有效的前 V 行按 expert_tokens 分组计算。
  5. npu_moe_distribute_combine_v2 沿 Dispatch 路径反向通信，将 [D, H] 的 expert 输出 unpermute，并使用 [T_local, K] 的权重合并为 [T_local, H]。
  6. Shared expert 始终处理本地 [T_local, H]，开启 side stream 时可与整个 gating -> dispatch -> GMM -> combine 路径重叠。
