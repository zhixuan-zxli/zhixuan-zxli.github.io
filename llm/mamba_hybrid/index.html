MambaHybrid: Align-Mode State Management (torch reference)

This document translates MambaHybridModelState.preprocess_state and postprocess_state (vllm/v1/worker/gpu/model_states/mamba_hybrid.py) into pure-torch reference implementations. The production versions launch fused Triton kernels (vllm/v1/worker/mamba_utils.py) that do everything GPU-side with no CPU-GPU sync (async-scheduling safe); the torch versions below are semantically equivalent but sync (.item()), so they are for understanding / debugging / CPU fallback, not performance.

Overview

Mamba/hybrid models store recurrent state (conv windows + SSM temporal state) in KV-cache blocks: each (layer, state-type) state tensor is block-major, [num_blocks, ...], indexed through the request’s block table.

With speculative decoding (and chunked prefill), the “running state” — the state after the last accepted token — can land at a position that is not a multiple of the mamba block size (128 tokens by default). Align mode (cache_config.mamba_cache_mode == "align") handles this with three pieces per step:

  1. preprocess_state (before the forward): advance the running-state pointer to the block containing the last token of this step’s chunk, and pre-copy the state into the new block column when a boundary is crossed, so the forward kernels read the initial state from the write-side block.
  2. The forward: kernels write state in-place; num_accepted_tokens is passed via attention metadata as the in-block bias.
  3. postprocess_state (after sampling): record how many tokens were accepted, and if acceptance left the sequence non-block-aligned, save the running state at the block-aligned position (start of the next block).

Called from the model runner at:

  • vllm/v1/worker/gpu/model_runner.py:1275 — preprocess_state, real batches only (dummy/profile runs skip it), before prepare_attn gathers num_accepted_tokens so the boundary reset is visible to the forward.
  • vllm/v1/worker/gpu/model_runner.py:1204 — postprocess_state, right after post_update has advanced num_computed_tokens to the post-step count.

State layout & invariants

Per-request-slot GPU buffers (created in __init__, mamba_hybrid.py:75-95):

Buffer Meaning
state_idx[req] Block-table column holding the running state; -1 = fresh
num_accepted[req] In-block bias; 1 = neutral non-spec value
src_col[req] Pre-advance column (scratch, emitted by preprocess)
src_off[req] Accepted-token bias = num_accepted - 1 (scratch)

Seeded in add_request (mamba_hybrid.py:97-105): num_accepted = 1, state_idx = (num_computed_tokens - 1) // block_size (handles resumed / chunked-prefill requests).

State tensor layouts, per (layer, state-type):

  • Temporal (conv_width == 0): [num_blocks, state_len, ...] — copy whole block, token_bias selects the source column (bt[src_col + bias]).
  • Conv, SD layout: [num_blocks, state_len, dim] — contiguous window; copy shifts the window by bias: state[bt[src], bias:] -> state[bt[dst], :cw-bias].
  • Conv, DS layout (is_conv_state_dim_first()): [num_blocks, dim, state_len] — same shift, applied per dim row.

The block tables passed to these kernels are batch-order slices of the persistent input_block_tables (mamba_hybrid.py:149-156), so a row is indexed by batch position, while the decision arrays are indexed by req slot — the two are related by idx_mapping (with -1 sentinels for filtered rows under PP).

Shared copy primitive

Both methods funnel their copies through _copy_mamba_state_block (mamba_utils.py:27). Torch equivalent:

def _copy_mamba_state_block_torch(
    state: torch.Tensor,      # [num_blocks, ...] block-major state tensor
    conv_width: int,          # >0 = conv, 0 = temporal
    bt_row: torch.Tensor,     # [max_blocks] int32 block ids for one batch row
    src_col: int,
    dst_col: int,
    bias: int,                # accepted-token bias
    dim_rows: int = 0,        # DS conv: dim rows per block
    dim_first: bool = False,  # DS conv layout
) -> None:
    dst_block = int(bt_row[dst_col].item())
    if conv_width == 0:
        # Temporal: state[bt[src_col + bias]] -> state[bt[dst_col]]
        src_block = int(bt_row[src_col + bias].item())
        state[dst_block] = state[src_block]
    elif dim_first:
        # DS conv (num_blocks, dim, state_len): per-dim-row window shift
        src_block = int(bt_row[src_col].item())
        state[dst_block, :dim_rows, : conv_width - bias] = state[
            src_block, :dim_rows, bias:conv_width
        ]
    else:
        # SD conv (num_blocks, state_len, dim): contiguous window shift
        src_block = int(bt_row[src_col].item())
        state[dst_block, : conv_width - bias] = state[src_block, bias:conv_width]

Notes:

  • Empty slices (bias >= conv_width, or negative lengths) are silent no-ops, matching the kernel’s masked-to-nothing copy.
  • torch evaluates the RHS before assignment, so it is overlap-safe even if src_block == dst_block physically; the kernel does a raw memcpy there.
  • Block ids are used as advanced indices into dim 0; the kernel’s int64 widening (state strides can exceed 2³¹ bytes) is implicit in torch.

preprocess_state

Production (mamba_hybrid.py:160-207) launches two kernels: preprocess_mamba_align_fused_kernel (per-request advance + param emission) then ctx.run_fused_precopy (per (request, state) copies).

def preprocess_state_torch(
    state_tensors: list[torch.Tensor],   # per (layer, state-type), block-major
    conv_widths: list[int],
    group_indices: list[int],            # per state: which mamba group
    dim_row_counts: list[int],           # per state: dim rows (DS conv)
    block_tables: list[torch.Tensor],    # per group, BATCH order [num_reqs, max_blocks] int32
    idx_mapping: torch.Tensor,           # [num_reqs] int32: batch -> req slot
    num_computed: torch.Tensor,          # [max_num_reqs] int32: pre-step computed count
    query_start_loc: torch.Tensor,       # [num_reqs + 1] int32
    state_idx: torch.Tensor,             # [max_num_reqs] int32, in/out
    num_accepted: torch.Tensor,          # [max_num_reqs] int32, in/out
    src_col: torch.Tensor,               # [max_num_reqs] int32 scratch, out
    src_off: torch.Tensor,               # [max_num_reqs] int32 scratch, out
    block_size: int,
    dim_first: bool = False,
) -> None:
    num_reqs = idx_mapping.shape[0]
    mask = idx_mapping >= 0
    req = idx_mapping.clamp(min=0)

    # Stage 1: advance state_idx + emit pre-copy params
    # (preprocess_mamba_align_fused_kernel, mamba_utils.py:282)
    old_state_idx = state_idx[req].clone()
    old_num_accepted = num_accepted[req].clone()

    src_col[req] = torch.where(mask, old_state_idx, src_col[req])
    src_off[req] = torch.where(
        mask, (old_num_accepted - 1).clamp(min=0), src_off[req]
    )

    query_len = query_start_loc[1:] - query_start_loc[:-1]
    computed_after = num_computed[req] + query_len
    new_state_idx = (computed_after + block_size - 1) // block_size - 1
    state_idx[req] = torch.where(mask, new_state_idx, state_idx[req])

    # Reset the bias to neutral (1) when the running state crosses a block
    # boundary: after migration it sits at the start of the new block.
    crossed = mask & (old_state_idx >= 0) & (old_state_idx != new_state_idx)
    num_accepted[req] = torch.where(
        crossed, torch.ones_like(new_state_idx), old_num_accepted
    )

    # Stage 2: migrate state across boundaries
    # (precopy_mamba_align_fused_kernel, mamba_utils.py:329)
    for b in range(num_reqs):
        if not mask[b].item():
            continue
        r = int(req[b].item())
        s = int(src_col[r].item())
        d = int(state_idx[r].item())
        if s < 0 or s == d:
            # Fresh request, or still writing the same block: the forward
            # locates the initial state in-block via num_accepted.
            continue
        bias = int(src_off[r].item())
        for state, cw, gid, nrows in zip(
            state_tensors, conv_widths, group_indices, dim_row_counts
        ):
            _copy_mamba_state_block_torch(
                state, cw, block_tables[gid][b], s, d, bias, nrows, dim_first
            )

Semantics per request: computed_after is the post-chunk computed count (pre-step num_computed + this step’s query_len); the running state moves to column ceil(computed_after / block_size) - 1. The pre-copy migrates the state from the pre-advance column (src_col, with bias num_accepted - 1) to the new column, so the forward can initialize from the write-side block.

postprocess_state

Production (mamba_hybrid.py:289-328) scatters the accepted counts (_scatter_num_accepted_kernel, or index_fill_ for a scalar), then — in align mode with a post-step num_computed_tokens — runs run_fused_postprocess_align (postprocess_mamba_fused_kernel with PRECOMPUTED_NEW_COMPUTED=True, HAS_IDX_MAPPING=True).

def postprocess_state_torch(
    state_tensors: list[torch.Tensor],
    conv_widths: list[int],
    group_indices: list[int],
    dim_row_counts: list[int],
    block_tables: list[torch.Tensor],    # per group, BATCH order
    idx_mapping: torch.Tensor,           # [num_reqs] int32: batch -> req slot (-1 skip)
    num_sampled: torch.Tensor | int,     # [num_reqs] int32 or scalar
    num_computed: torch.Tensor,          # [max_num_reqs] int32: post-step computed count
    state_idx: torch.Tensor,             # [max_num_reqs] int32, in
    num_accepted: torch.Tensor,          # [max_num_reqs] int32, in/out
    block_size: int,
    dim_first: bool = False,
) -> None:
    num_reqs = idx_mapping.shape[0]
    mask = idx_mapping >= 0
    req = idx_mapping.clamp(min=0)

    # Stage 1: record accepted counts. Neutral value is 1: chunked-prefill
    # rows sample nothing (num_sampled == 0) but mamba treats 1 as non-spec.
    if isinstance(num_sampled, int):
        vals = torch.full(
            (num_reqs,), max(num_sampled, 1),
            dtype=torch.int32, device=idx_mapping.device,
        )
    else:
        vals = num_sampled.clamp(min=1)
    num_accepted[req] = torch.where(mask, vals, num_accepted[req])

    # Stage 2: save the running state at the block-aligned position when
    # acceptance left the sequence non-block-aligned
    # (postprocess_mamba_fused_kernel, mamba_utils.py:154)
    for b in range(num_reqs):
        if not mask[b].item():
            continue
        r = int(req[b].item())
        new_comp = int(num_computed[r].item())
        num_acc = int(num_accepted[r].item())
        src = int(state_idx[r].item())

        # Position (1-based) of the state currently saved in the running
        # block: the always-accepted sampled token of this step.
        running_pos = new_comp - num_acc + 1

        aligned = (new_comp // block_size) * block_size
        if aligned < running_pos:
            continue  # accepted progress stayed within the running block

        bias = aligned - running_pos
        dst = aligned // block_size - 1

        if src == dst:
            num_accepted[r] = 1  # state stays in the running block: neutral bias
        if src == dst and bias == 0:
            continue  # no-op self-copy

        for state, cw, gid, nrows in zip(
            state_tensors, conv_widths, group_indices, dim_row_counts
        ):
            _copy_mamba_state_block_torch(
                state, cw, block_tables[gid][b], src, dst, bias, nrows, dim_first
            )

Decision logic: running_pos is where the saved state currently sits (the sampled token is always accepted, regardless of draft rejections); new_comp is the post-step computed count = position of the last accepted token. If the accepted progress reaches a block boundary at or beyond the saved position (aligned >= running_pos), the running state is re-saved at that boundary: shifted forward by bias tokens into column aligned // block_size - 1 — i.e. the state at the start of the next block, which is what the next step’s preprocess/forward expects as its initial state. The num_accepted = 1 reset covers the same-block case: the state stays where it is and the in-block offset convention restarts at the block start.

Why GPU-resident?

The two production kernels run unconditionally each step and fast-exit per request (src_col < 0 or src_col == dst_col in preprocess; aligned < running_pos in postprocess). Skipping the launches would require an async D2H of the actual num_computed, since num_computed_tokens_np is an optimistic mirror under async scheduling — the launch cost is ~0.3% of TPOT, so the GPU fast-exit wins (mamba_hybrid.py:181-186).

Caveats of the torch reference

  • .item() calls sync GPU→CPU per request; use them for reference/testing only. A GPU-only variant would keep everything as tensors (the temporal copies vectorize to one advanced-index assignment; conv copies need per-bias bucketing because the slice length varies).
  • Block tables must be batch order (V2); the V1 kernel variant (HAS_IDX_MAPPING=False) uses req-slot order with req_idx = batch_idx.
  • The V1 postprocess variant (PRECOMPUTED_NEW_COMPUTED=False) derives the positions from pre-step values instead: running_pos = num_computed + num_scheduled - num_draft and new_comp = running_pos + num_accepted - 1, and writes the reset to a separate output buffer instead of in place.
  • Only align mode is covered here; the “all” mamba cache mode has its own lighter-weight bookkeeping (postprocess_mamba_all, mamba_utils.py:1140).
