chunk_kda_fwd Kernel Walkthrough

A kernel-by-kernel analysis of chunk_kda_fwd (fla/ops/kda/chunk_fwd.py:20), focused on the KDA path and context parallelism (CP). For each Triton kernel: a reference torch implementation, input/output shapes, and the grid layout.

Notation and global shapes

  • $q, k \in \mathbb{R}^{B \times T \times H \times K}$ — queries/keys, $H$ q/k heads, head dim $K$
  • $v \in \mathbb{R}^{B \times T \times H_V \times V}$ — values, $H_V = H \cdot G$ value heads (GQA group size $G$), value dim $V$
  • $g \in \mathbb{R}^{B \times T \times H_V \times K}$ — per-channel log-decay gate (per value head)
  • $\beta \in \mathbb{R}^{B \times T \times H_V}$ — delta-rule write strength
  • $\text{BT} = \text{chunk\_size}$ (default 64), $\text{BC} = 16$ (sub-chunk), $\text{NC} = \text{BT}/\text{BC}$ (4 when BT=64)
  • $\text{RCP\_LN2} = 1/\ln 2$ — scaling that turns $\exp(\cdot)$ into $\exp_2(\cdot)$ for kernel speed

The KDA recurrence being chunked is (per value head, dropping batch):

$$ S_t = \exp(g_t) \odot S_{t-1} + \beta_t \, k_t \otimes \bigl(v_t - k_t^\top S_{t-1}\bigr), \qquad o_t = q_t^\top S_t $$

where $\odot$ is element-wise (channel-wise) gate, $\otimes$ is the outer product $k \otimes v = k v^\top \in \mathbb{R}^{K \times V}$.

1. Gate preparation — one of two paths

1a. use_gate_in_kernel=True → kda_gate_chunk_cumsum_vector_kernel

File: fla/ops/kda/gate.py:375. Fuses activation + bias + chunk-local cumsum.

Torch reference

# g_raw: [B, T, H, K], A_log: [H], dt_bias: [H*K] or None
g = g_raw + dt_bias.view(H, K) if dt_bias is not None else g_raw
g = -A_log.exp().view(H, 1) * F.softplus(g)        # [B, T, H, K], in log2 space
g = g * RCP_LN2                                    # convert to log2 base
# chunk-local cumsum along T with chunk_size=BT
g = g.view(B, NT, BT, H, K).cumsum(dim=2).view(B, T, H, K)

Mathematical formula

$$ g_{t,k} \leftarrow \frac{1}{\ln 2} \sum_{\tau = \lfloor t/\text{BT}\rfloor \cdot \text{BT}}^{t} -\exp(A_{\text{log}}) \cdot \text{softplus}(g_{\tau,k} + b_k) $$

Shapes — in: $g[B,T,H,K],\; A_{\text{log}}[H],\; dt\_bias[H*K]?$; out: $g[B,T,H,K]$ (fp32).

Grid: (cdiv(K, BS), NT, B*H) — i_s tiles the $K$ dim, i_t is the chunk, i_bh is batch×head. Each program computes a $[\text{BT}, \text{BS}]$ tile, applies bias and $-\exp(A_{\text{log}}) \cdot \text{softplus}(\cdot)$, then tl.cumsum along the BT axis.

1b. use_gate_in_kernel=False (default) → chunk_local_cumsum_vector_kernel

File: fla/ops/utils/cumsum.py:90. Skips activation — assumes g is already the log-decay; just rescales by $\text{RCP\_LN2}$ and chunk-cumsums.

Torch reference

g = (g * RCP_LN2).view(B, NT, BT, H, K).cumsum(dim=2).view(B, T, H, K)

Mathematical formula

$$ g_{t,k} \leftarrow \frac{1}{\ln 2} \sum_{\tau = \lfloor t/\text{BT}\rfloor \cdot \text{BT}}^{t} g_{\tau,k} $$

Shapes — in/out: $[B, T, H, K]$ (here $H$ is $H_V$ because $g$ has value-head dim).

Grid: (cdiv(S, BS), NT, B*H) with $S = K$. Same tiling as 1a but no activation, just tl.cumsum and scale.

2. Intra-chunk: chunk_kda_fwd_intra (fla/ops/kda/chunk_intra.py:818)

Returns $w, u, q_g, k_g, A_{qk}, A_{kk}$. Internally calls three Triton kernels.

2a. Diagonal sub-blocks — chunk_kda_fwd_kernel_intra_token_parallel (default) or chunk_kda_fwd_kernel_intra_sub_chunk (safe_gate)

These compute the diagonal $\text{BC} \times \text{BC}$ blocks of the intra-chunk attention matrices:

  • $A_{qk}[i, j] = \text{scale} \cdot (q_i \odot \exp(g_i - g_j)) \cdot k_j$ for $j \le i$ (lower-triangular), diagonal sub-chunks only
  • $A_{kk}[i, j] = \beta_i \cdot (k_i \odot \exp(g_i - g_j)) \cdot k_j$ for $j < i$ (strictly lower, since diagonal is consumed by the solve)

The $A_{kk}$ diagonal blocks are stored separately in Akkd (fp32) for precision during the triangular solve.

Torch reference (matches the loop in naive_chunk_kda, fla/ops/kda/naive.py:127-136)

# A_qq: [B, HV, NT, BT, BT] (only diagonal BC-blocks filled)
# A_kk: [B, HV, NT, BT, BC] (only the strictly-lower part of the diagonal BC-block, fp32)
for i in range(BT):
    k_i = k[..., i, :]
    g_i = g[..., i:i+1, :]
    Aqk_diag[..., i] = (q * exp(g - g_i)).sum(-1) @ k_i.T   # only j in same sub-chunk
    Akk_diag[..., i] = (k * exp(g - g_i)).sum(-1) @ k_i.T * beta[..., i]
Akk_diag = Akk_diag.masked_fill(mask_upper_or_diag, 0)

Mathematical formula (for tokens $i, j$ in the same sub-chunk)

$$ A_{qk}[i, j] = \begin{cases} \text{scale} \cdot \sum_d q_{i,d} \, k_{j,d} \, \exp_2(g_{i,d} - g_{j,d}) & j \le i \\ 0 & \text{otherwise} \end{cases} $$$$ A_{kk}[i, j] = \begin{cases} \beta_i \cdot \sum_d k_{i,d} \, k_{j,d} \, \exp_2(g_{i,d} - g_{j,d}) & j < i \\ 0 & \text{otherwise} \end{cases} $$

The kernel then computes the diagonal inverse $(I + \text{tril}(A_{kk}^{\text{diag}}))^{-1}$ via forward substitution in registers.

Shapes:

  • in: $q, k, g_k[B, T, H/H_V, K]$, $\beta[B, T, H_V]$, $\text{scale}$
  • out: $A_{qk}[B, T, H_V, \text{BT}]$ (lower-triangular row of the chunk matrix, q.dtype), $A_{kkd}[B, T, H_V, \text{BC}]$ (fp32)

Grid for chunk_kda_fwd_kernel_intra_token_parallel (fla/ops/kda/chunk_intra_token_parallel.py:33): (B*T, cdiv(HV, BH)) — one program per (token, head-group). Each program loads $q_t, k_t, \beta_t$ and loops over $j$ from sub-chunk start to $i_t$, doing one token row of $A_{qk}$/$A_{kk}$. This “token-parallel” layout avoids wasted compute on padded tokens in varlen.

Grid for chunk_kda_fwd_kernel_intra_sub_chunk (fla/ops/kda/chunk_intra.py:683): (NT, NC, B*HV) — one program per (chunk, sub-chunk, batch×value-head). Loads a $[\text{BC}, \text{BK}]$ tile of $q, k, g$, computes $b_{A_{qk}} = (q \odot g_q) \cdot (k \odot g_k)^\top \cdot \text{scale}$, $b_{A_{kk}} = (k \odot g_q) \cdot (k \odot g_k)^\top \cdot \beta$, masks to lower-triangular, writes to $A_{qk}$/$A_{kkd}$, then runs an in-register forward-substitution to invert $(I + \text{tril}(A_{kk}))$ for this BC-block. Uses gather for the reference gate row when hardware supports it (numerical stability).

2b. Off-diagonal blocks + merged inverse — chunk_kda_fwd_kernel_inter_solve_fused

File: fla/ops/kda/chunk_intra.py:43. Computes the off-diagonal $A_{qk}$ and $A_{kk}$ sub-blocks (within a chunk, across the $\text{NC}=4$ sub-chunks), then assembles the merged inverse $(I + \text{tril}(A_{kk}^{\text{chunk}}))^{-1}$ block-by-block using the already-inverted diagonal blocks loaded from Akkd.

Torch reference (continuing naive_chunk_kda)

# Off-diagonal sub-blocks (i_s > j_s)
for i_s in range(NC):
    for j_s in range(i_s):
        Aqk_chunk[:, i_s*BC:(i_s+1)*BC, j_s*BC:(j_s+1)*BC] = (
            q_blk_i * exp(g_i - g_j)) @ k_blk_j.T * scale
        )
        Akk_chunk[:, i_s*BC:(i_s+1)*BC, j_s*BC:(j_s+1)*BC] = (
            k_blk_i * exp(g_i - g_j)) @ k_blk_j.T * beta_i
        )

# Forward-substitution inverse of (I + tril(Akk_chunk)) — block-triangular inverse formula
Akk_inv = block_tril_inverse(Akk_chunk, Akkd_inv)  # see lines 269-351

Mathematical formula (block-triangular inverse for $\text{NC}=4$ sub-chunks, denoting $A_{kk}^{ij}$ the $(i, j)$ sub-block):

$$ \begin{aligned} A_{kk}^{-1,00} &= (I + A_{kk}^{00})^{-1} \quad \text{(from Akkd)} \\ A_{kk}^{-1,11} &= (I + A_{kk}^{11})^{-1} \quad \text{(from Akkd)} \\ A_{kk}^{-1,10} &= -A_{kk}^{-1,11} \, A_{kk}^{10} \, A_{kk}^{-1,00} \\ A_{kk}^{-1,21} &= -A_{kk}^{-1,22} \, A_{kk}^{21} \, A_{kk}^{-1,11} \\ A_{kk}^{-1,20} &= -A_{kk}^{-1,22} \bigl( A_{kk}^{20} A_{kk}^{-1,00} + A_{kk}^{21} A_{kk}^{-1,10} \bigr) \\ A_{kk}^{-1,30} &= -A_{kk}^{-1,33} \bigl( A_{kk}^{30} A_{kk}^{-1,00} + A_{kk}^{31} A_{kk}^{-1,10} + A_{kk}^{32} A_{kk}^{-1,20} \bigr) \\ &\;\;\vdots \end{aligned} $$

Shapes:

  • in: $q, k, g_k, \beta$, $A_{kkd}[B, T, H_V, \text{BC}]$ (fp32, diagonal inverses from 2a)
  • out: $A_{qk}[B, T, H_V, \text{BT}]$ (now full chunk matrix, q.dtype), $A_{kk}[B, T, H_V, \text{BT}]$ (full inverse, q.dtype)

Grid: (NT, B*HV) — one program per (chunk, batch×value-head). Each program:

  1. Loops $i_k$ over $K$-tiles, accumulates the 6 (NC=4 → 6) off-diagonal $\text{BC} \times \text{BC}$ blocks of $A_{qk}$ and $A_{kk}$ in registers.
  2. Stores off-diag $A_{qk}$ blocks to global, multiplies off-diag $A_{kk}$ blocks by $\beta$.
  3. Loads the 4 diagonal $A_{kk}^{-1}$ blocks from $A_{kkd}$ (fp32).
  4. Combines them with the merged inverse formula above using tf32 precision (lines 315-351).
  5. Stores the full $A_{kk}$ inverse to global.

2c. WY representation — recompute_w_u_fwd_kda_kernel

File: fla/ops/kda/wy_fast.py:34. Builds the WY factorization needed for the inter-chunk recurrence:

  • $u = A \cdot v$ where $A = (I + \text{tril}(A_{kk}))^{-1}$ (computed above)
  • $w = A \cdot (\beta \odot k \odot \exp(g))$ (gated, beta-scaled keys)
  • $k_g = k \odot \exp(g_{\text{last}} - g)$ (key aligned to chunk-end for the state update)
  • $q_g = q \odot \exp(g)$ (optional, only if disable_recompute=True)

Torch reference (naive_chunk_kda lines 138-139)

A_inv = Akk                                              # [B, HV, NT, BT, BT]
w = A_inv @ (exp(g) * k)                                 # [B, HV, NT, BT, K]
u = A_inv @ v                                            # [B, HV, NT, BT, V]
qg = q * exp(g)                                          # optional
kg = k * exp(g_last - g)                                 # for state update

Mathematical formula

$$ u_t = \sum_{j \le t} A_{kk}^{-1}[t, j] \, v_j, \qquad w_t = \sum_{j \le t} A_{kk}^{-1}[t, j] \, \beta_j \, k_j \, \exp_2(g_j) $$$$ k_{g,t} = k_t \odot \exp_2(g_{\text{last}} - g_t), \qquad q_{g,t} = q_t \odot \exp_2(g_t) $$

Shapes:

  • in: $k[B, T, H, K]$, $v[B, T, H_V, V]$, $\beta[B, T, H_V]$, $A = A_{kk}[B, T, H_V, \text{BT}]$, $g_k[B, T, H_V, K]$, optional $q$
  • out: $w[B, T, H_V, K]$, $u[B, T, H_V, V]$ (alias for v_new later), $k_g[B, T, H_V, K]$, $q_g[B, T, H_V, K]?$

Grid: (NT, B*HV). Each program loops over BT rows of $A$, computes $u = A \cdot (\beta_v \odot v)$ for BV-tiles of $V$, then $w = A \cdot (\beta \odot k \odot \exp(g))$ for BK-tiles of $K$ (lines 92-128). Same program writes $q_g$ and $k_g$ if requested.

3. CP pre-processing — only when cp_context is not None

chunk_gated_delta_rule_fwd_h_pre_process (fla/ops/cp/chunk_delta_h.py:747) builds the initial state for this rank by gathering per-rank chunk-summary matrices from earlier ranks. It uses two Triton kernels plus an all-gather.

3a. pre_process_fwd_kernel_merged (skip on is_last_rank)

File: fla/ops/cp/chunk_delta_h.py:41. Each rank computes a per-rank summary $(h_{\text{rank}}, M_{\text{rank}})$ of shape $[H_V, K, V+K]$, where:

  • $h_{\text{rank}}$ (the $[:, :, :V]$ part) is the “forced” state contribution of this rank’s tokens assuming $h_0 = 0$:
$$ h_{\text{rank}} = \sum_t k_t^\top \bigl(v_t - w_t \, h_{t-1}\bigr) \cdot \exp_2(g_{\text{last}} - g_t) $$
  • $M_{\text{rank}}$ (the $[:, :, V:]$ part, $K \times K$) is the chunked transition matrix:
$$ M_{\text{rank}} = \prod_t \bigl(\text{diag}(\exp_2(g_{\text{last}})) - k_t^\top w_t\bigr) $$

$M_{\text{rank}}$ propagates an arbitrary $h_0$ through this rank’s tokens.

Torch reference (conceptual)

# h0 arbitrary; for the rank starting fresh, h0=0
h = h0                                              # [HV, K, V]
M = eye(K)                                          # [HV, K, K]
for chunk in rank_chunks:
    v_new = v_chunk - w_chunk @ h                   # delta-rule update
    v_new *= exp(g_last - g_chunk)                  # gate-align to chunk end
    h = h * exp(g_last) + k_chunk.T @ v_new         # state update
    M = (diag(exp(g_last)) - k_chunk.T @ w_chunk) @ M
# Output: hm[:, :, :V] = h, hm[:, :, V:] = M  (per rank, [HV, K, V+K])

Shapes:

  • in: $k, w, u, g_k$ (only last sequence via cu_seqlens[-2:]), $\text{bg} = \text{None}$ for KDA (KDA path uses USE_GK=True, USE_BG=False)
  • out: $h_m[H_V, K, V+K]$ (fp32)

Grid: (cdiv(V, BLOCK_SIZE) + cdiv(K, BLOCK_SIZE), HV). Each program handles either the $h$ part ($i_{\text{col}} < \text{cdiv}(V, \text{BS})$, computes a $[64, \text{BLOCK\_SIZE}]$ tile of $h$ via the recurrence) or the $M$ part ($i_{\text{col}} \ge \text{cdiv}(V, \text{BS})$, computes a $[\text{BK1}, \text{BLOCK\_SIZE}]$ tile of $M$). Note $\text{BK1} = \text{next\_power\_of\_2}(K)$.

3b. all_gather_into_tensor

A torch.distributed collective (not Triton) — gathers $h_m$ across all CP ranks into $ag_{hm}[\text{world\_size}, H_V, K, V+K]$. See fla/ops/cp/comm.py.

3c. merge_fwd_bwd_kernel with FORWARD=True (skip on is_first_rank)

File: fla/ops/cp/chunk_delta_h.py:332. Folds the per-rank summaries from all preceding ranks into this rank’s initial_state.

Torch reference

# h0 for this rank = composition of all previous ranks' (h_rank, M_rank)
h = zeros(HV, K, V)
for prev_rank in ranks_before_me:
    h_prev, M_prev = ag_hm[prev_rank]              # h_prev: [K, V], M_prev: [K, K]
    h = M_prev @ h + h_prev                        # fold previous rank's contribution
initial_state[0] = h                               # [N=1, HV, K, V]

Mathematical formula

$$ h_0^{(\text{this rank})} = \sum_{r \in \text{prev\_ranks}} \left( \prod_{r' \le r} M_{r'} \right) h_r \;=\; M_{r_1} h_{r_0} + M_{r_2}(M_{r_1} h_{r_0} + h_{r_1}) + \cdots $$

Iteratively: $h \leftarrow M_r \, h + h_r$ for each previous rank $r$ in order.

Shapes:

  • in: $ag_{hm}[\text{world\_size}, H_V, K, V+K]$, $\text{pre\_num\_ranks}$, $\text{rank}$
  • out: $\text{initial\_state}[N, H_V, K, V]$ (or $[N, H_V, V, K]$ if state_v_first)

Grid (CP mode): (cdiv(V, BV), HV) — $i_v$ tiles $V$, $i_h$ is the head. Each program loops over $\text{pre\_num\_ranks}$ previous ranks, loads $(h_{\text{prev}}, M_{\text{prev}})$ tiles, and accumulates $h = M_{\text{prev}} \, h + h_{\text{prev}}$ (line 441-453). When state_v_first=True the layout is transposed: $h^\top{}' = h^\top \, M^\top + h_{\text{prev}}^\top$.

3d. compress_h0 (fla/ops/cp/chunk_delta_h.py:923) — pure torch

Returns initial_state[:1].clone(). Only the first sequence in the local batch can be a CP continuation, so the rest is dropped to save memory for save_for_backward. No kernel.

4. Inter-chunk state recurrence — chunk_gated_delta_rule_fwd_h

File: fla/ops/common/chunk_delta_h.py:50, kernel chunk_gated_delta_rule_fwd_kernel_h_blockdim64. Computes the per-chunk hidden states $h[0 \ldots \text{NT}-1]$ and $v_{\text{new}}$ (the delta-rule-corrected values), using the initial_state from step 3 (or the user-supplied one in non-CP mode).

Torch reference (matches naive_chunk_kda lines 160-163)

S = initial_state                                  # [N, HV, K, V]
v_new_chunks = []
for i in range(NT):
    v_new = u_i - w_i @ S                          # delta-rule: subtract predicted from v
    v_new_gated = v_new * exp(g_last_i - g_i)      # align to chunk end
    h[i] = S                                       # store state at chunk start
    S = S * exp(g_last_i) + k_i.T @ v_new_gated    # state update with gated new value
final_state = S

Mathematical formula (per chunk $i$, with $S$ the running state)

$$ v_{\text{new}}^{(i)} = u^{(i)} - w^{(i)} \, S_{i-1} $$$$ \tilde{v}^{(i)}_t = v_{\text{new},t}^{(i)} \odot \exp_2(g_{\text{last}}^{(i)} - g_t) $$$$ S_i = \text{diag}(\exp_2(g_{\text{last}}^{(i)})) \, S_{i-1} + k^{(i)\,\top} \, \tilde{v}^{(i)} $$$$ h[i] = S_{i-1}, \qquad \text{final\_state} = S_{\text{NT}} $$

Shapes:

  • in: $k[B, T, H, K]$, $w[B, T, H_V, K]$, $u[B, T, H_V, V]$, $g[B, T, H_V]?$, $g_k[B, T, H_V, K]?$, $\text{initial\_state}[N, H_V, K, V]?$
  • out: $h[B, \text{NT}, H_V, K, V]$ (or $[B, \text{NT}, H_V, V, K]$ if state_v_first), $v_{\text{new}}[B, T, H_V, V]$, $\text{final\_state}[N, H_V, K, V]?$

Grid: (cdiv(V, BV) * N * HV,) — one program per (V-tile, sequence, head). Each program iterates NT chunks, maintaining 1-4 register tiles of size $[64, \text{BV}]$ (one per 64-wide $K$ slice, since $K \le 256$). Per chunk: stores current $h$ tile, computes $v_{\text{new}} = u - w \, h$, applies gate decay $\exp_2(g_{\text{last}} - g)$, decays $h$ by $\exp_2(g_{\text{last}})$ and $\exp_2(g_{k,\text{last}})$ (per-channel), then $h \mathrel{+}= k^\top v_{\text{new}}$. Final chunk’s $h$ is stored to final_state.

5. Output projection — chunk_gla_fwd_o_gk → chunk_gla_fwd_kernel_o

File: fla/ops/gla/chunk.py:345. Computes the final attention output by combining the inter-chunk state contribution and the intra-chunk attention.

Torch reference (naive_chunk_kda line 161)

# o_i = (q_i * exp(g_i)) @ h[i] + Aqk_i @ v_new_i
o = (qg @ h_inter) + Aqk @ v_new                  # [B, HV, NT, BT, V]

Mathematical formula

$$ o^{(i)} = \bigl(q^{(i)} \odot \exp_2(g^{(i)})\bigr) \, h[i] \cdot \text{scale} + A_{qk}^{(i)} \, v_{\text{new}}^{(i)} $$

Shapes:

  • in: $q[B, T, H, K]$, $v = v_{\text{new}}[B, T, H_V, V]$, $g[B, T, H_V, K]$, $A = A_{qk}[B, T, H_V, \text{BT}]$, $h[B, \text{NT}, H_V, K, V]$, $\text{scale}$
  • out: $o[B, T, H_V, V]$ (zeros-initialized — vLLM pads $v$)

Grid: (cdiv(V, BV), NT, B*HV) — $i_v$ tiles $V$, $i_t$ is the chunk, $i_{bh}$ is batch×value-head. Each program:

  1. Loops $i_k$ over $K$-tiles, loads $q, g, h$ tiles, accumulates $b_o = (q \odot \exp_2(g)) \, h$.
  2. Multiplies by $\text{scale}$.
  3. Loads $v_{\text{new}}$ and the lower-triangular $A_{qk}$ row for this chunk, adds $A_{qk} \, v_{\text{new}}$.
  4. Stores $o$.

CP flow recap

In non-CP mode, step 3 is skipped and initial_state flows directly from the user into step 4. In CP mode:

  1. Each non-last rank computes its $(h_{\text{rank}}, M_{\text{rank}})$ summary (3a) — $M_{\text{rank}}$ is the linear transfer matrix that propagates any $h_0$ across this rank’s tokens.
  2. Summaries are all-gathered (3b).
  3. Each non-first rank folds all preceding ranks’ summaries into its initial_state (3c) via $h \leftarrow M_r \, h + h_r$.
  4. compress_h0 (3d) trims to a single sequence for backward’s save_for_backward.

This avoids ever materializing or communicating full $[K, V]$ states per chunk across ranks — only one $[K, V+K]$ summary per rank is gathered, giving CP overhead that’s independent of sequence length.
