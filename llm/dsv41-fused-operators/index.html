DeepSeek V4.1-Flash：SWA / Compressor / Indexer 融合算子
2026-10-29 00:00 label DeepSeek   推理  

代码位置按当前 checkout 标注（DeepInfer @ 2c37138）；shape 使用 T / B 记号。

本文按 SWA、Compressor、Indexer 三条链路分类，说明模型脚本中实际使用的融合算子、合并 GEMM、TileLang 索引/搬运 kernel，以及它们在 prefill / decode 下的数据流和 tensor shape。

文中三张架构图较宽，点击图片可查看原尺寸。

0. 结论速览

这三块一共用到 4 个融合 kernel 家族：

融合 kernel 家族 融合内容 使用位置
fused_norm_rope_hadamard_cast_store_kvcache RMSNorm + RoPE + cast + store；可选 cast_back，也可输出 pre-RoPE 副产物 SWA KV、Compressor 主 KV、Indexer Q/K
fused_norm_rope_attn_rope_cast Q RMSNorm + RoPE + sparse MLA + 输出反 RoPE + FP8 cast SWA prefill / decode
compress_and_update_state_{prefill,decode} state 读写 + 逐维 softmax + 加权和 + bf16 Compressor C2
DeepGEMM mqa_logits 系列 GEMM + ReLU + head 加权归约 Indexer logits

这里的 4 个是底层 kernel 家族；同一个 fused_norm_rope_hadamard_cast_store_kvcache 会在 SWA / Compressor / Indexer 重复出现，因此按子系统拆开会看到 6 个使用类别。

另有 3 处合并 GEMM（host 侧拼权重，仍是一次普通 GEMM）：

合并 GEMM 权重拼接 使用位置
q_a_kv_swa_proj [Wq.A ∥ Wkv.A] SWA 共用前端
q_b_proj [Wq.B ∥ index q_B] SWA + Indexer 共用
current_hidden_proj [Gate ∥ A ∥ index weights_proj] Compressor 共用前端

以及一组 TileLang 索引/搬运 kernel：expand_swa_index、kv_index_cat、get_kv_swa_index_decode、load_paged_kv_cache、store_kv_cache、candidate_block_max、get_candidate_compact_lens、restore_candidate_indices_inplace、convert_kv_index。

说明：fused_norm_rope_hadamard_cast_store_kvcache 名字里带 Hadamard，但 SWA / Compressor / Indexer 三条路径的调用点都是 hadamard_args=None；HadamardArgs 只在测试里出现。

1. 口径与 shape 记号

1.1 分类口径

  • FUSED：一个 kernel 内完成 ≥ 2 个逻辑阶段，例如 norm + rope + cast + store、state 更新 + softmax + 加权和。
  • MERGED GEMM：host 侧把多个权重 concat 成一个权重，仍然只 launch 一次普通 GEMM；它不是 kernel 内融合，但确实减少了 launch 和中间张量。
  • TILELANG：专用索引/搬运 kernel，可能同时做量化/反量化，但不属于多阶段计算融合。
  • VENDOR：FlashMLA、DeepGEMM、DeepSelect 等外部 kernel。

2. SWA：滑动窗口注意力

2.1 模块职责

SWA 分支负责：

  1. 从 hidden states 一次投影出 q_a 和 kv_swa；
  2. 把 kv_swa 做 norm + RoPE + FP8 量化，写入 swa_cache；
  3. prefill 时把历史 SWA KV、当前 KV、压缩 KV 拼成连续 buffer，并把 SWA 索引与压缩 topk 索引拼成一条 kv_index；
  4. decode 时把 swa_cache 的 ring slot 和 ca_cache 的 paged slot 作为两组 indices，传给同一个 FlashMLA。

2.2 融合算子

算子 类型 融合阶段 输入 → 输出 代码位置
fused_norm_rope_hadamard_cast_store_kvcache FUSED RMSNorm → RoPE（尾 64）→ FP8 E4M3 per-32 cast → store kv_swa [T/B,512] → swa_cache；prefill 走 cast_back 出 bf16 attn.py:402-451、fused_transform.py:189
fused_norm_rope_attn_rope_cast.prefill FUSED Q RMSNorm + RoPE → sparse MLA + sink → 输出反 RoPE → FP8 cast q_raw [T,N_h·512] + kv [K_v,512] → context [T,N_h,512] attn.py:589-626、attention_backend.py:29
fused_norm_rope_attn_rope_cast.decode FUSED Q RMSNorm + RoPE → SWA/CA 双缓存 sparse MLA + sink → 输出反 RoPE → FP8 cast q_raw [B,N_h·512] + swa_cache + ca_cache → context [B,N_h,512] attn.py:628-670、attention_backend.py:74

2.3 KV_SWA 融合写

_prepare_swa_kv（attn.py:402-451）把四件事合成一次 kernel：

  1. RMSNorm(kv_swa_norm)；
  2. RoPE，作用在最后 64 维，offset = 512 - 64 = 448；
  3. FP8 E4M3 per-32 量化，scale 为 UE8M0；
  4. store 到 swa_cache。

prefill 和 decode 的差异：

  • prefill：CastArgs(..., cast_back=True)，输出 bf16；如果 CP > 1，再对 kv_swa 做 all_gather。由于 ring slot 可能与历史读区间重叠，当前 KV 的 store_kv_cache 必须等 load_paged_kv_cache 读完历史后再执行。
    • 这意味着 prefill 会做一次“量化 round-trip → bf16”，store 时再量化一次；代码里这是有意的顺序约束。
  • decode：KVCacheOutArgs(swa_cache, slot_mapping_store_swa)，直接写量化后的 cache，不返回 bf16。

Hadamard 在本模型没有启用。

2.4 Q 路径与 FlashMLA 的融合边界

主 Q 的 norm+RoPE 默认不在投影后单独做，而是折叠进注意力 kernel：

  • 当 use_fused_norm_rope_attn_rope_cast 为真时，q_b_proj 的输出 q_raw 保持“未 norm、未 RoPE”的状态，直接送进 prefill_attn_varlen_sparse / decode_mla_mqa_sparse；
  • fused_norm_rope_attn_rope_cast 在 kernel 内完成 Q RMSNorm、RoPE、sparse MLA、attention sink、输出反 RoPE，以及给 WV einsum 用的 per-32 FP8 cast；
  • 这个路径要求 GPU 且 num_heads ∈ {64, 128}；否则退回“同一个 fused transform 单独做 norm+RoPE → 普通 FlashMLA”，数值等价。

Q 的单算子 fallback 在 _q_b_norm_rope（attn.py:158-172）： fused_norm_rope_hadamard_cast_store_kvcache，只做 norm + RoPE，不做 cast/store。

2.5 两个合并 GEMM

GEMM 拼接 输出 说明
q_a_kv_swa_proj [Wq.A ∥ Wkv.A] q_a [T/B,Rq]、kv_swa [T/B,512] 一次 GEMM 出两路；YOCO shared-hidden 场景改走独立 kv_swa_proj
q_b_proj [Wq.B ∥ index q_B] q_raw [T/B,N_h·512]、index_q_b [T/B,N_i·128] 主 Q 与 indexer Q 共用一次 GEMM；split 后分别使用

2.7 prefill / decode 数据流

Prefill

hidden [T,H]
  ├─ q_a_kv_swa_proj ──► q_a [T,Rq] ──► q_b_proj ──► q_raw [T,N_h·512]
  │                                                   index_q_b [T,N_i·128]
  └─ kv_swa [T,512] ──► fused norm+rope+cast（cast_back）
                         ├─► CP all_gather（可选）
                         └─► store_kv_cache
swa_cache（历史）──► load_paged_kv_cache ──► kv [K_v,512]
kv_swa（当前）────────────────────────────┘
expand_swa_index ──► kv_index_cat ──► kv_index [T,W+K]
q_raw + kv + kv_index ──► fused sparse MLA ──► context [T,N_h,512]

Decode

swa_cache + ca_cache
get_kv_swa_index_decode ──► swa_idx [B,W]
kv_ca_index（Indexer） ──► ca_idx [B,K]
q_raw [B,N_h·512] + 两组 indices
  └─► fused decode MLA（双缓存 + sink）──► context [B,N_h,512]

2.8 格式与 shape

  • swa_cache：MXFP8，逻辑 shape [blocks, W_s, 512]，每 token 512 个 E4M3 值 + 16 个 UE8M0 scale = 528 B/token。
  • context：[T,N_h,512] / [B,N_h,512]，融合输出为 (fp8, sf)。
  • kv_index：prefill [T,W+K] int32；decode 为 [B,W] + [B,K] 两组索引。

3. Compressor：压缩 KV

3.1 模块职责

Compressor 把 kv_compress_ratio = N 个连续 token 的 KV 压成一个 compressed KV：

  • C2 使用 Gate 产出的 score 与 A 产出的 latent，逐维做 2-token softmax，再对 latent 加权求和；
  • 压缩后的 KV 做 RMSNorm、RoPE、量化，写入主 KV cache ca_cache；
  • 同时把 post-norm、pre-RoPE 的 KV 作为 pre_rope_kv 副产物交给 Indexer 的 KProject；
  • C1 没有 Gate、没有 state cache，投影结果直接进入 norm/rope/cast/store。

3.2 融合算子

算子 类型 融合阶段 输入 → 输出 代码位置
compress_and_update_state_prefill FUSED 旧窗口 state + 新 token → 逐维 softmax(N=2) → 加权和 → bf16；第二段 grid 写 state tail score/latent [T,512] × 2 → kv_compressed [T/N,512] tilelang_ops/compress.py:20、cuda/compress.py:31
compress_and_update_state_decode FUSED 写当前 token 到 state ring → 块尾行 softmax + 加权和；非块尾行输出 0 score/latent [B,512] × 2 → kv_compressed [B,512] tilelang_ops/compress.py:74、cuda/compress.py:187
fused_norm_rope_hadamard_cast_store_kvcache FUSED RMSNorm → RoPE（compressed positions）→ cast → store；out_stage=norm 产出 pre-RoPE 副产物 kv_compressed [T/N 或 B,512] → ca_cache + pre_rope_kv [T/N 或 B,512] compress.py:131-167、fused_transform.py:189

3.3 C2 压缩 kernel 的细节

数学形式（逐 channel j）：

c_t[j] = Σ_{i=0}^{1} softmax_i(score_{t-i}[j]) · latent_{t-i}[j]

prefill kernel（cuda/compress.py:31-185）：

  1. 第一段 grid：对每个 compressed block，读取旧窗口（来自 state_cache）和新 token 的 score/latent，做逐维 softmax + 加权和，输出 bf16；
  2. 第二段 grid：把每个序列尾部 state_cache_size 个 token 的 score/latent 写回 state ring；
  3. 两段之间用 T.pdl_sync() 同步；
  4. CP 场景通过 HAS_INDEX 和 mirror_cp_reverse_index 读取重排后的 score/latent。

decode kernel（cuda/compress.py:187-292）：

  1. 第一段 grid：把当前 token 的 score/latent 写入 state ring；
  2. 第二段 grid：只对 (context_len - 1) % N == N - 1 的块尾行做 softmax + 加权和；
  3. 非块尾行输出 0，slot_mapping_store_ca = -1，不会污染 KV cache。

3.4 主 KV 融合写

forward_store_kv_cache（compress.py:131-167）用同一个 fused transform 完成：

  • RMSNorm（compressor 的 norm）；
  • RoPE，位置来自 positions_c（压缩坐标，block_idx * N）；
  • cast：由 cache layout 决定
    • use_fp4_sparse_kv：FP4 E2M1，16 values / E4M3 scale，288 B/token；
    • 否则：MXFP8 E4M3，32 values / UE8M0 scale，528 B/token；
  • store 到 ca_cache，slot 来自 slot_mapping_store_ca；
  • out_stage="norm" 时额外输出 post-norm、pre-RoPE 的 pre_rope_kv，供 Indexer 的 KProject 使用。

Hadamard 同样未启用。

3.5 合并投影

current_hidden_proj 把三个权重拼成一次 bf16 GEMM（attn.py:328-373）：

[Gate ∥ A ∥ index weights_proj] · hidden
  → projected_kv [T/B, 2·512] fp32（C2）
  → split: score [T/B,512] | latent [T/B,512] | index_weights [T/B,N_i]
  • C2：use_fp32_output=True，Gate/A 不参与 FP8 量化；
  • C1：没有 Gate，只有 A，输出 bf16；
  • index_weights 会转成 bf16 交给 Indexer。

3.6 CP 与共享

  • CP：projected_kv 的 all_gather 先 launch，与 Q 投影重叠；prefill 压缩前用 mirror_cp_reverse_index 做 gather 重排（compress.py:91-92）。
  • 下游：prefill 的 load_paged_kv_cache 把压缩段 gather 成连续 bf16（attn.py:832-842）；decode 直接按 paged slot 读 ca_cache。
  • 跨层共享：SharedLayerTopology 把 KV / index-K / index-topk 三段共享解耦；kv source 只写一次 ca_cache / pre_rope_kv，consumer 只读。
  • C1 边界：forward_pre_norm 直接返回 bf16 投影，跳过两个 compress kernel，仍走 STAGE 2 的 norm+rope+cast+store。

3.7 格式与 shape

  • state_cache：[slots, S, 2, 512] fp32，score / latent 双通道。
  • ca_cache：逻辑 [blocks, C, 512]，token-interleaved [data | scale]；每 token 288 B（FP4）或 528 B（MXFP8）。
  • pre_rope_kv：prefill [T/N,512] bf16；decode [B,512] bf16（非块尾行为 0）。

4. Indexer：稀疏索引器

4.1 模块职责

Indexer 为每个 query 选 top-k 个 compressed KV：

  1. Q 做 RoPE + FP4 量化；
  2. K 由主 compressor 的 pre_rope_kv 经 KProject 投影，再做 RMSNorm + RoPE + FP4 量化，写入 ica_cache；
  3. 计算 relu(q·k) 的 head 加权 logits p_sum；
  4. 在 p_sum 上做候选块限制（可选）和 token top-k；
  5. decode 时把逻辑 token 索引经 block_tables 转成物理 slot。

4.2 融合算子

算子 类型 融合阶段 输入 → 输出 代码位置
Q: fused_norm_rope_hadamard_cast_store_kvcache FUSED 只做 RoPE（use_q_norm=False）→ FP4 E2M1 per-32 cast index_q_b [T/B,N_i·128] → q_fp4 [T/B,N_i,128] + q_sf [T/B,N_i,4] index_attn.py:164-179
K: KProject + fused_norm_rope_hadamard_cast_store_kvcache GEMM + FUSED Linear 512→128 → RMSNorm → RoPE(64) → FP4 → store pre_rope_kv [T/N 或 B,512] → ica_cache index_attn.py:133-162、compress.py:32-53
fp8_fp4_mqa_logits / ..._sparse / ..._paged... VENDOR FUSED FP8/FP4 MQA GEMM + ReLU + head 加权求和 q_fp4 + ica_cache → p_sum [T/B,L_c] index_attn.py:284-325、421-454

K 路径的 KProject Linear 和 fused transform 是两次 launch；不要把它理解成“线性层也在这个 fused kernel 里”。K 的 cache 写入只在 index-K source 层发生，consumer 复用 ica_cache。

4.3 Q 与 K 的不对称

  • Q：MQAIndexer.use_q_norm = False，所以 Q 的 fused transform 只做 RoPE + FP4，不做 RMSNorm；
  • K：KProject 先做 Linear 512→128，随后 fused transform 做 RMSNorm + RoPE + FP4 + store；
  • q_sf 的 4 个 scale 来自 128 / 32；FP4 张量按逻辑 128 维标注，物理上按 E2M1 packed。

4.4 DeepGEMM logits 融合

四个变体：

路径 dense candidate
prefill fp8_fp4_mqa_logits fp8_fp4_sparse_mqa_logits
decode fp8_fp4_paged_mqa_logits fp8_fp4_paged_sparse_mqa_logits

计算语义：

p_sum[t,s] = Σ_h w[t,h] · ReLU(q[t,h] · k[s])

DeepGEMM kernel 内完成 matmul、ReLU、head 加权求和，直接输出 p_sum。本模型 Q/K 都是 FP4 E2M1；API 名保留 fp8_fp4_*，SM100 输出 bf16，SM90 输出 fp32。

配套的 metadata 由 DeepGEMM 生成：

  • get_sparse_mqa_logits_metadata
  • get_paged_mqa_logits_metadata
  • get_paged_sparse_mqa_logits_metadata

它们不是计算 kernel，但决定了 logits 的稀疏调度。

4.5 候选块与 top-k 索引链

算子 类型 作用 代码位置
candidate_block_max TILELANG 块内 max、valid blocks，最后一个有效块置 +inf candidate_blocks.py:12
deep_select.topk VENDOR block 级 / token 级 topk，sorted int32，越界填 -1 index_attn.py:216/361/494
get_candidate_compact_lens TILELANG 候选块覆盖的有效 token 数 candidate_blocks.py:77
restore_candidate_indices_inplace TILELANG compact 索引恢复成 sequence-local / 全局索引 candidate_blocks.py:114
convert_kv_index TILELANG decode 时逻辑 token 索引 → 物理 paged slot flash_mla_utils.py:10
load_paged_kv_cache TILELANG prefill 时按 FP4 layout 读取 index-K（value + sf） index_attn.py:181-202

候选块路径是可选的共享层优化：candidate source 层先选 block，后续 consumer 只在这些 block 内算 sparse logits。

4.6 共享层行为

  • index-K source：跑 KProject + fused transform + store ica_cache；
  • index-K consumer：不跑 KProject/store；prefill 直接复用 source 的 loaded_prefill_index_kv；
  • index-topk source：写 cross_layer_runtime.topk_indices；
  • index-topk consumer：复用 source 的 topk，不再跑自己的 logits/topk。

4.7 格式与 shape

  • ica_cache：逻辑 [blocks, C, 128]，每 token 64 B FP4 data + 4 B UE8M0 scale = 68 B/token。
  • q_fp4：[T/B, N_i, 128]（逻辑），q_sf：[T/B, N_i, 4]。
  • p_sum：prefill [T, L_c]，decode [B, L_c]。
  • topk_index：prefill [T, K] / decode [B, K] int32；prefill 是 gathered-kv 全局索引，decode 是物理 slot。

prefill 特殊处理 先 load 历史、后 store；两次量化 两段 grid + PDL；state tail 写回 加载 FP4 index-K；候选块可选
decode 特殊处理 SWA/CA 双缓存一次注意力 块尾行才计算，非块尾置 0 paged logits + 物理 slot 转换
与另一块的耦合 用 kv_index_cat / dual-cache 与压缩 KV 合流 产出 pre_rope_kv 给 Indexer 产出 topk_index 给 SWA/核心注意力

5.1 容易误判的点

  1. Hadamard 未启用：三条路径都传 hadamard_args=None，不要因为算子名就认为它在做 Hadamard 变换。
  2. SWA prefill 两次量化：fused transform 先 cast_back 成 bf16，store_kv_cache 再量化；这是“先 load 后 store”的顺序约束导致的。
  3. Q 的 norm+RoPE 不一定单独执行：GPU + 64/128 heads 时折叠进 FlashMLA；否则才走独立 fused transform。
  4. SWA/CA 只有两个合流点：prefill 的 kv_index_cat 和 decode 的 dual-cache。除此之外两条 KV 路径是分开的。
  5. dense 层没有 indexer：kv_ca_index 由 get_kv_ca_index_prefill/decode 展开，不是 topk。
  6. C1 走独立分支：C1 跳过 Gate、state_cache 和两个 compress kernel，但仍走主 KV 的 norm+rope+cast+store。
  7. KProject 不在 fused kernel 内：K 路径是 GEMM + fused transform 两次 launch。

6.1 全量算子速查

SWA

  • FUSED：fused_norm_rope_hadamard_cast_store_kvcache（KV_SWA）
  • FUSED：fused_norm_rope_attn_rope_cast.prefill/decode
  • MERGED GEMM：q_a_kv_swa_proj、q_b_proj
  • TILELANG：expand_swa_index、kv_index_cat、get_kv_swa_index_decode、load_paged_kv_cache、store_kv_cache
  • 可选：get_kv_ca_index_prefill/decode（dense 层）
  • CP：all_gather / gather

Compressor

  • FUSED：compress_and_update_state_prefill、compress_and_update_state_decode
  • FUSED：fused_norm_rope_hadamard_cast_store_kvcache（主 KV）
  • MERGED GEMM：current_hidden_proj
  • TILELANG：gather（CP 重排）
  • CP：all_gather

Indexer

  • FUSED：Q fused_norm_rope_hadamard_cast_store_kvcache
  • GEMM + FUSED：K KProject + fused_norm_rope_hadamard_cast_store_kvcache
  • VENDOR FUSED：DeepGEMM mqa_logits 四变体
  • TILELANG：candidate_block_max、get_candidate_compact_lens、restore_candidate_indices_inplace、convert_kv_index、load_paged_kv_cache
  • VENDOR：deep_select.topk
